# Photography Editorial Style Guide

**适用范围：** Liam Frost · Photography Portfolio

**版本：** 1.0 · 2026-11-28

**地位：** 摄影文字及分类编辑的 Single Source of Truth。用于人工维护、ChatGPT、Codex、Claude 及后续 Agent；不替代网站的数据验证规则、安全规范或摄影者的明确决定。

> 文字应当服务于摄影作品，而不是通过文字重新制造一件不存在的艺术作品。

## 1. Editorial Philosophy — 编辑理念

本作品集是独立摄影作品的长期陈列。作品的色调、构图、观看距离、取景方式已足以建立它的视觉身份。文字的职责是识别作品、提供必要的语境、帮助检索，并通过无障碍文字让图像可被理解；并不承担替作品解释意义或证明艺术价值的任务。

好的摄影标题不一定解释照片；**好的摄影描述也不一定需要存在。** 每一个字段必须有自己的功能。尤其不要把标题写成图片识别结果，再把识别结果扩写成所谓作品阐述，并重复三遍给替代文本。

| 字段                   | 编辑职责                 | 判断标准                                   |
| ---------------------- | ------------------------ | ------------------------------------------ |
| Title                  | 识别、命名、建立观看入口 | 读完仍愿意看照片；不抢占照片的解释权       |
| Description            | 语境与观察增量           | 不看这段文字，观众会失去哪项有价值的信息？ |
| Alt text               | 传达关键可见信息         | 无法看图的人能否理解主体、空间与构成？     |
| Category               | 主导摄影对象或观察方式   | 只能有一个主要类别；不同类别具有可识别边界 |
| Tags                   | 跨类别检索               | 指向真实可见或已核实的概念；不堆叠同义词   |
| Location / Date / EXIF | 事实记录                 | 来源明确；未知不补造                       |

### 1.1 当前作品集的视觉基线

2026-11-28 生产后台显示 58 张公开作品（18 张站内上传、40 张 Flickr 引用），无隐藏作品。本次基线来自完整画幅的显示图：新作来自后台实际图像，旧作来自存档的 Flickr `b` 显示图；不是由旧标题或 Alt Text 推导。

- **色彩与亮度。** 大量作品以冷青、蓝绿和暖橙/赭色并置，暗部面积明显；东京夜景用点状暖光与大块冷调建筑建立层次。优胜美地及太平洋近岸作品以暗林、青色海水与受光岩面、沙岸或暮色形成对照。也有明亮例外，如画廊的白砖墙和黄色画作、深蓝天幕下的红花。
- **构图。** 从高处俯视城市、铁路和海岸；从低处仰视塔、屋檐和穹顶；让窗框、梁柱、枝叶、栏杆或近处雕石成为第二层框架。并非每张都是大景：灯具、门匾、机车、猫和绘马也承担独立的形式研究。
- **空间。** 全球城市中的密集楼群、线缆、招牌、行人、交通通道，与海岸和山地的大尺度、建筑细部的近距离观察形成对照。人物往往是尺度或街道关系的一部分；不应自动被描述成孤独、疏离或寻找自由。
- **重复与差异。** 同一观察点可产生不同作品：涩谷高处的晴空塔、东京塔、铁路、体育场和城市夜景各有不同构图命题。新宿的两张过街照片是相近场景的不同瞬间。格里菲斯的露台与街灯、Locarno Beach 的木构近景与城市远景也可相互参照。但不能据此建立未经摄影者确认的正式系列。

上述是对图像的编辑观察，**不是摄影者心理、经历、审美动机或价值观的陈述**。将其用作编辑语汇的参考，而非把每张照片写成同一主题。

## 2. Title System — 命名体系

### 2.1 按作品选择方法，而不是分配模板

先决定影像怎样成立，再决定怎样命名。允许短词、地名、街名、具体器物、局部符号、完整句子、简短形式概念或经确认的系列编号。不要按类别统一模式，也不规定字数、词性、句式配额。

| 方式              | 使用条件                                         | 例（本作品集或示例）                                             |
| ----------------- | ------------------------------------------------ | ---------------------------------------------------------------- |
| 地理/地标         | 地标具体可核实，名称本身有辨识性                 | El Capitan / 酋长岩；Half Dome / 半圆顶；Space Needle / 太空针塔 |
| 地点与时间/条件   | 有可靠的环境或时间线索，能区分同地作品           | San Francisco, After Dark；Griffith Observatory at Dusk          |
| 标识与文字        | 标识或可辨认文字是作品构成的一部分               | One Way；敬天                                                    |
| 形式研究          | 画面颜色、构造、几何、取景本身是关键             | Interior in Amber；立面；结构                                    |
| 纪实/场所         | 具体场所或活动比概念词更有意义                   | 歌舞伎町一番街；江户川花火大会                                   |
| 有根据的概念/短语 | 抽象词与该张画面的特征或关系紧密相连             | 离岸；东京折叠；木与海                                           |
| 对象              | 对象的名称就是合理的作品题名，无需制造第二层含义 | 绘马；水母；小黑                                                 |
| 无题/编号         | 摄影师确有无题或编号意图；或有明确的形式系列     | Untitled, 2026；不为填字段而虚构系列编号                         |

### 2.2 编辑选择顺序

1. 独立观看全幅，标出区别于其它作品的两三项事实（例如前景是深色横梁，焦点在向右的英文路牌，而非“城市”）。
2. 确认已有可靠地点、标题中真正的专名、可辨识的文字。原题若已经简洁、准确且独特，先考虑保留，其次仅修复个别语言。
3. 至少考虑直接命名、形式命名与地点命名三个方向（不必全部产出）。选择最适合当前作品的一种；不要在同一批重复机械结构。
4. 把候选放在同地点/对象作品旁边阅读。如果能够互换，进一步具体化，或使用可核实的地名；不刻意为了差异而制造陌生词。
5. 标题的多语版本按各语言独立润色；仅在意义确实共享时复用专名。

### 2.3 禁用形式

- 以视觉识别列表充当标题（除非直接命名是有意的摄影编辑选择）。不要逐张写成「X 里的 Y」「X 上的 Y」「X 下的 Y」。
- 拟人化物件：门楣守望、穹顶回声、钟楼诉说时间等没有画面依据的叙事。不要以「守望」「低语」「回响」「凝望」「诗篇」「时光」「永恒」「静谧」等作为批处理词库。
- 以任意抽象词掩盖图像差异：Stillness、Solitude、Beyond、Echoes、Elsewhere 不因简短或英语而自动成为好标题。
- 误把照片描绘的图画、标牌、节庆造型当作拍摄的真实对象；不要因 ID、文件名或旧标题包含地点就替作品新增事实。
- 不为所有作品添加编号，不以 Untitled 逃避审查；不擅改摄影者确认的题名、专名或私人昵称。

## 3. Description Guidelines — 描述 / 编辑说明

**默认提出问题而不是默认写句子：这张照片确实需要一段文字吗？** 如果标题、地点、日期和 Alt Text 已足够，完整地置空描述，比追加一句辞藻优雅但没有增量的文字更专业。

### 3.1 允许的增量

- 提供确认的拍摄语境（日期、场所、活动等，但不机械复述已经独立展示的元数据）。
- 提示可以通过观看验证的构成关系，例如：画框之外还有一层门窗开口、相邻作品采用同一地点的不同视距。与 Alt Text 重叠时，以更重要的观察理由或对照关系为核心，而不是再说一遍「画面中有……」。
- 说明可核实的文字、建筑、文化类型；短而有必要，例如绘马的惯用文化语义；不揣测写字人的身份、祈愿具体结果或摄影者赋予的宗教/政治含义。
- 可靠的现场历史背景、照片系列关系；如来自照片之外的事实，应有来源或作者确认。没有来源就不扩展。

通常只需一至两句自然语言。也可留空、仅有一句说明、或者在需要时用较完整的策展文字。长度由信息量而非字段配额决定。

### 3.2 删除规则

删除空泛形容词、照抄可见内容、批量重复的“光线引导目光”“夜色接管城市”“时间放慢”等感悟；禁止虚构场景前后发生什么、摄影者的经历或动机、人的情感和身份。无法证实的类别/对象使用可观察的描述或明确不确定性。避免“仿佛……”“诉说着……”“在……之间寻找……”“定格了……”等万能句型；不是因为词本身一律错误，而是它们在摄影文案中极易替代真实观察。

**编辑核验不是作品文案。** 将事实核查、置信度、排除项、隐私判断、命名理由和写作过程留在内部编辑记录。尊重观众自己的判断，不解释显而易见的事实，不告诉观众应该看什么、不应该看什么。除非否定或不确定性本身具有理解作品所需的信息价值，不使用「并非实际……」「不需要读出……」「根据作品集记录……」「题名所指的是……」等自我辩解语句。能正常陈述的关系直接陈述；缺少事实则省略，不以免责声明代替。所有公开字段和五语版本均适用。

### 3.3 空值是有意的编辑结果

实际模型的 `description` 为 `LocalizedText | null`。后台编辑器在五语均无非空内容时提交 `null`；API 底层去除空白字符串。前台 `PhotoModal` 通过 `description ? ... : null` 判断，不渲染空描述段落。若只删除一个语言键，而其他语言有文字，回退可能显示其他语言的描述，因此决定不写时，应五语均清空并持久化为 `null`，不是写入 `""`、`—`、`N/A` 或伪造一句话。

## 4. Accessibility & Alt Text — 无障碍编辑

依据 [W3C WAI Images Tutorial](https://www.w3.org/WAI/tutorials/images/)、[Alt Decision Tree](https://www.w3.org/WAI/tutorials/images/decision-tree/) 与 [WCAG 非文本内容 1.1.1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html)。作品照片在作品集是**信息性图像**，并非纯装饰；替代文本须反映其在该页面的意义。W3C 的原则是视实际上下文决定文本替代，不要求任意统一字数。本网站照片卡片与详情都传入作品 `alt`，因此每种站点语言都应有真实、自然、非空的替代文本。

### 4.1 编写方法

- 以主体和独特空间关系优先，必要时补充辨识性的颜色、光线、取景位置和关键可读文字。前景遮挡、景深、近景与远景对应关系在本作品集尤其重要。
- 与陈列文字相协调：专名若对理解主体有价值可以使用；不机械重复标题、地点、日期、评语及拍摄设置，不需要“照片中”“这张照片展示”等起手式。
- 描述可见事实，颜色与方向要准确；不从虚化细节猜测身份/物种/品牌/路线/活动，也不把镜头造成的取景误当作航空摄影。使用“从高处俯瞰”，除非确有航拍依据。
- 可读的关键标牌应准确保留原文，例如 `ONE WAY`；外语版本可说明意思。摄影中个人手写内容只在理解作品不可或缺且适当时概述，不转录不必要的个人信息。
- 禁止文学替代文本、情绪推断、SEO 堆词和相机参数。系统最大长度为 300 字符（具体以当前 API 校验为准），应在此范围内表达重要信息，不设置主观的最少词数。

### 4.2 示例

《One Way》：`A tilted black-and-white ONE WAY sign points right; shaded buildings and a glimpse of water recede behind it.` 这说明了画面的视觉重心、可读文字、箭头、空间深度。不说“一个寻求自由的单向旅程”。

《离岸》：`A small figure is partly visible above the surf below an orange sky and distant hills. Two birds cross the sky; dark bands border the top and bottom.` 只描述可验证的人、水、天空、取景遮挡；不猜测其身份或为何下水。

## 5. Multilingual Editorial Guidelines — 五语本地化

实际语言键：`zh`（简体中文，**不是** `zh-CN`）、`zh-Hant`（繁體中文）、`en`、`fr`、`ja`。`LocalizedText` 是这些语言键的部分映射。前台 `getPhotoField` 当繁体键缺失时优先回退简体再英语；其他语言键缺失时优先英语再简体。照片标签逐个使用同样的本地化规则。后台编辑器允许缺失并提示回退，**编辑后的必要字段不得依赖回退替代专业本地化**。不要为此改动已有语言配置。

| 语言     | 约束与实践                                                                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 简体中文 | 自然现代、对照准确。一词可成题（如「结构」「绘马」），专名采用常见中文写法。避免四字格堆叠、文言断句和「在……中」翻译体。                                                                              |
| 繁體中文 | 不只是字形转换，选择自然词语：「檔案」「機車」「義大利」「晴空塔／東京鐵塔」「標誌」等依语境选用；和简体保持同一对象。                                                                                |
| English  | Gallery/book-title register。专名保留官方拼写；简洁名词、自然短语，标点与大小写风格适当；不直译中文隐喻，不用无意义串词。标题 Title Case 可用，不要求每个普通词首字母大写。Alt 使用完整、易读的英语。 |
| Français | 自然法语的介词、冠词、性数、重音与引号。题名不强制英语式 Title Case；优先 `Tokyo, la nuit`、`Coupole du Palais des Beaux-Arts` 等自然结构，正确处理 `d’`、`à`，不照搬英语名词串。                     |
| 日本語   | 地名和建筑采用惯用日本写法（例：道頓堀、渋谷、歌舞伎町一番街、東京タワー）。题名可以是名词短语，不照搬汉语四字格或外来词；Alt 使用自然的日语语序，避免无端使用「〜が形成する」。                      |

五语不需要逐字镜像，允许不同表达但作品指向、风格、具体事实一致。照片指向 Pismo Beach 时可在中文写「皮斯莫海滩」，英文用 `Pismo Beach`，而不是把官方地名再按字面翻译。专名有明确原文（`One Way` road sign、`敬天` 匾额）时，在其他语言以原文或准确解释保留辨识信息。日期只在确认且有编辑价值时进入标题。作品被命名为《小黑》时，仍应尊重原题；在外语采用转写可避免将名称误解为对毛色的描述，不声称这是猫真实的名字。

## 6. Category & Taxonomy — 分类体系

现有 `Nature`、`City`、`Street`、`Architecture`、`Daily Life`、`Travel` 并不是严格互斥，尤其 `Travel` 描述行程而非作品主导内容；它实际收纳花火、水母、塔、寺额和绘马。使用主导题材的六类设计，保留已有五个有效类别的英文 key（网站使用英文分类作为筛选身份），将 `Travel` 逐张迁回合适类别，并用 `Culture` 承接仪式、活动及展陈。无需新字段、迁移或改系统配置。

| 稳定键 `en`  | zh   | zh-Hant | fr           | ja         | 边界                                                                        |
| ------------ | ---- | ------- | ------------ | ---------- | --------------------------------------------------------------------------- |
| Nature       | 自然 | 自然    | Nature       | 自然       | 山地、海岸、水域、动植物；环境尺度或生物主体主导。                          |
| City         | 城市 | 城市    | Ville        | 都市       | 城市整体、天际线、区域空间及基础设施网络；视角常在高处或远处。              |
| Street       | 街头 | 街頭    | Rue          | ストリート | 行人、交通信号、街道、招牌及在街面发生的关系。                              |
| Architecture | 建筑 | 建築    | Architecture | 建築       | 建成形体、建筑材质/结构、装饰细部或空间构成主导。                           |
| Daily Life   | 日常 | 日常    | Quotidien    | 日常       | 私人/生活环境、熟悉的物件、室内、日常动物。                                 |
| Culture      | 文化 | 文化    | Culture      | 文化       | 艺术陈列、庆典、文化物件和仪式相关场景；并不意味着所有寺庙/旅行照片都归此。 |

**决策边界：** 东京高处俯观铁路是 City，信号灯与行人是 Street，东京塔钢架特写是 Architecture，栏边乌鸦是 Nature，窗边的猫是 Daily Life；绘马和花火是 Culture。使用视角和主导主体决定，不通过单个可见物体抢占分类。不为少数照片新增 Portrait、Abstract、Night、Japan 等类别；这些若有意义应是标签或经确认的系列。每个类别在所有语言中只有一组本地化值，不把 `City` 和 `Urban` 当成两种身份。

## 7. Tagging System — 标签

`tags` 为 `LocalizedText[]`，数组中每一对象是一项跨语语义身份。没有独立标签 ID 或别名系统，故所有复用词条固定一组五语对应值，并将同义词收敛。类别、地点本身均参与搜索，不需要将其逐条复制为标签。标签不是搜索引擎关键词密度策略。

- 优先选择可跨照片检索的具体对象与环境（海岸、海浪、植物、鸟类、铁路、标牌、街灯、展览、绘马、烟火、钟楼、木构）、形式和光线条件（仰视、俯瞰、逆光、暮色、夜景、留白、几何、框景）。
- 在明确的比较价值下可使用具体地标标签（如多地点可检索 `Tokyo Tower`、`Tokyo Skytree`）；仅当标签为检索入口时使用。避免每张都贴 `City`、`Photography`、`Beautiful`、`Travel`、`Light` 或难以核实的概念如 `Order and Chaos`、`Time`。
- 不猜物种、具体历史建筑、时间、天气、模特身份或未确认摄影类别；无需固定数量，0 项也是有效选择。不要机械混用单复数/不同大小写/重复同义词。
- 以用户检索为目标，典型 2–5 项但不作为配额；照片卡片只展示部分标签，详情页展示全部，因此较关键的标签先列。无确认标签则空数组 `[]`。

## 8. Location & Factual Metadata — 事实元数据

事实的优先级：摄影者确认/可核实现场记录与原图 EXIF → 已有可靠记录与照片可验证文字 → 权威来源（仅用于确认专名或客观背景）→ 未知。不能将视觉猜测升级成事实。现有地名/日期有冲突时，记录待查，不覆盖未经核实的拍摄元数据。仅确证的笔误与语言本地化修正可在地点字段应用，保持地理范围不扩大。

- 地点应使用可确认的最精细层级，按各语言自然顺序书写，保留现有可核实地标。`location` 可为 `null`；不要从 ID 推断城市、街道、国家或精确坐标。跨语言不引入不同地点。原「道顿堀」而画面标牌读作「黒門市場商店街」的例子需摄影者核实实际拍摄位置；可以客观说明照片里文字，但不可擅改地点。
- 拍摄日期独立于 `source.importedAt`、`createdAt`、`updatedAt`。已见上传时 API 用 EXIF 日期或当日作为后备；所以 18 张上传作品都写 2026-11-10、相机字段全空，并不证明该日拍摄。当前 API `date` 要求 `YYYY-MM-DD`，不可通过猜想替换；记录待核实并保留现值。无法提供合法日期时应先向摄影者申请，不编造日份。
- 相机、镜头、曝光参数包括焦距、快门、光圈、ISO 只能来自原图 EXIF、经摄影者确认的记录。`null` 是未知；不要为这些字段增加文本占位。现有 `Canon Samung S22` 明显可疑但不能猜测真实型号，不修正为另一个型号。不得将照片构图、像素尺寸等用于推断器材参数。
- 正式系列需摄影者确认；不按批次文件名推出系列，不虚构编号，也不擅自增加模型字段。相近照片可在描述中明确比较视觉形式，但不是正式系列。
- 图像版本、文件、存储路径、关联、ID、公开状态、精选、排序、浏览量均不可因文字编辑改动。系统自动维护更新时间不是拍摄日期。由于公开列表在同日以标题并列排序，改名可能改变同日视觉排序，不能因此改动 `sortOrder` 或排序代码。

## 9. Anti-AI Writing Guidelines — 反模板编辑

不要以同义词替换掩盖没有内容的句子。优先保留现有真正有效题名。一个优秀的题名可以是「鹿」或「皇穹宇」，不必是「在时间的缝隙中聆听山风」。单张检查后再做集合检查。

| 测试         | 操作                                                                                       | 不合格处理                                                               |
| ------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 可替代性     | 把标题/描述拿到十张不同作品旁，是否同样适用？                                              | 返回独特视觉观察、具体地点，或删去描述                                   |
| 信息增量     | 分别读标题、地点与 Alt，描述究竟新增了什么？                                               | 若无增量，则 `null`                                                      |
| 过度诠释     | 指出文字的每个带意义判断由哪项事实或可见关系支撑                                           | 去掉虚构故事、拟人、人格和情绪确定性                                     |
| 自然语言     | 分别朗读五语，想象独立摄影作品编辑而非译者                                                 | 重写翻译腔，保留语言自身节奏                                             |
| 防御性与说教 | 这句话是在增加观众能获得的信息，还是在证明编辑没有弄错、限制观众如何观看、解释为何这样写？ | 删除自我辩解、免责声明、观看指令和核验口吻；保留有价值的陈述，必要时置空 |
| 集合一致性   | 将同类、同地、同日、相邻作品多语题名并列；读所有描述                                       | 修复可互换、结构重复、语义重复及误指对象                                 |

不要把一致性理解为统一句长/词性/意象。刻意将作品轮流编号、固定每张一行诗、统一为抽象英文一词，均不是专业编辑。风格是判断标准的一致，而不是句式的一致。

### 10.1 单张发布前检查清单

- [ ] 按作品 `id` 取得对应最高可用质量**完整画幅**，不以图片文件名/旧题/缩略图替代观看；记录预览质量与原图不可用的限制。
- [ ] 选择保留或修改原题的理由，核实专名、无题/系列及描述增量；不凭取景推断作者意图。
- [ ] 五语 `title` 非空且各自自然、语义对齐；`alt` 五语非空、具体、忠实、无虚构；描述要么五语完整，要么 `null`。
- [ ] 公开文字不出现内部审查口吻、无必要的否定、隐私提醒、自我说明或观看指令；不把事实确认过程当作作品内容。
- [ ] 主导类别唯一，英文分类键一致；标签无空值、重复或同义堆叠，五语含义一致。
- [ ] 确认已知地点；不修改未核实的日期、EXIF、设备及系列，未知事实列入待核查。
- [ ] 带 ID 备份原始字段（必须是当前线上值），明确实际更新的字段；不要重新上传图片或发出其它修改请求。
- [ ] 通过管理接口逐张保存，回读对照预期值；检查五语公开列表/详情、回退、乱码与意外截断。

### 10.2 集合发布前检查清单

- [ ] 在同地点、同对象和跨地点作品间并列阅读标题，检查自然变化、重复、错误地标及无依据的文学性。
- [ ] 检查描述的真实价值，特别是所有被强制填充的散文；保留真实增量，不追求统一非空率。
- [ ] 检查五语分类、可检索标签和同义词表；确保没有空语种依赖不合适回退。
- [ ] 对所有 `id` 完成对照，查明任何未审图、未应用、未回读的作品，显式标明其状态。
- [ ] 第二轮审查独立处理发现的问题；在所有受保护字段未改变、编辑字段持久化且页面显示核实后，才可声称已上线。

## 11. Data contract / change control

遵循实际 `AdminPhoto` / `AdminPhotoUpdate`（`packages/shared/src/api.ts`）和 `apps/api/src/lib/validation.ts`。本次编辑只允许提交 `title`, `description`, `alt`, `category`, `tags` 和经确认的 `location`。API `PATCH /api/admin/photos/:id` 是严格的局部更新接口；不发读写其它字段、不使用图像版本操作、不修改数据库直接存储或绕过认证。提交前逐项对比当前记录与备份，若出现并行修改，先重新核实，不覆盖。后台 UI 可能提交整个 draft；在使用它之前应确认受保护字段从未变更，并回读验证。

`null` 是可空字段的明确缺省；描述 `null` 表示有意不写，而相机/镜头/设置 `null` 表示未知。标签 `[]` 是明确无标签。稀疏 patch 中字段未出现代表不修改，不等于清空。API 校验：title 最长 120，category/每个标签 40，location 120，description 1000，alt 300 字符；tags 数组至多 20，标题至少一语非空。编辑规范要求必要字段五语齐全，比 API 最低约束更严格。保存前检查实际版本接口及回退，不变更配置。

对未知事实、预览质量限制、不可逆操作或用户专属命名背景，记录问题并等待确认；可逆、可查证的文字编辑无需逐图询问。只有在取得当前原始字段备份和可靠图像后才应用；如果无法完成，交付明确标记为待应用的修订及客观阻碍，不用过时快照冒充上线结果。
