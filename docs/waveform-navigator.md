# Waveform navigator

The desktop home page has one SVG rail, 18 visual segments and a separate semantic button for each section that actually exists. `useSections` measures the real document and responds to content, image and size changes; the rail maps positions to document positions, while the active mark tracks scrolling. The existing hash router and `ScrollManager` perform navigation and restore saved scroll positions on back/forward. The rail is hidden below 1280px or without a hover-capable fine pointer; the existing mobile navigation remains available. Other routes currently have only one meaningful top-level section, so do not show the rail.

`useWaveMotion` combines a damped Gaussian pointer peak, scroll progress and, while music plays, a simulated signal in one requestAnimationFrame loop. It updates SVG attributes without React renders and stops when idle or hidden. Reduced-motion disables pointer and music motion while retaining section buttons and progress. The preview uses existing theme tokens and derives titles and summaries from the rendered section content.

The music motion is simulated, never read from the audio (`syntheticEnergy` in `model.ts`: a ~112 bpm pulse shared by all lines plus faster waves whose phase differs per line). While music plays a line grows by up to `PLAYING_AMPLITUDE` (24 of the 64-wide viewBox; the hover peak is 35.2), and it settles back as soon as playback stops. `audio-visualization.ts` only knows whether something plays:

- The site's own player: the `playing`, `pause`, `ended` and `error` events of its single HTMLAudioElement. The audio is not captured or analysed.
- Spotify's embedded player: a plain iframe in the dock, as before PR #62's bridge, so a signed-in visitor hears full tracks. The embed itself posts `playback_started` and `playback_update` (`isPaused`) to the page; only messages from `https://open.spotify.com` whose source is the dock's iframe count. Without an update for 4 seconds (it sends about one a second while playing) the rail returns to rest.

PR #62 had put Spotify's IFrame API in a sandboxed bridge (a same-origin sandboxed iframe that replaced itself with a `data:` document). Spotify's frame then had an opaque ancestor and no storage access (`document.hasStorageAccess()` false, true in a plain iframe), so it could not see the visitor's sign-in and only played 30-second previews. The bridge was removed; the plain embed's own messages give the same playback state without loading Spotify's script on the page.

`apps/api/test/waveform.test.ts` covers navigation boundaries, Gaussian shape, the simulated signal (bounded, visible, below the hover peak), the Spotify messages (origin and frame checks, string or object data, silence timeout) and the site player's events. Browser checks should cover playback in both player modes, a signed-in Spotify account playing full tracks, keyboard/focus, pointer transitions, section navigation/history, reduced motion and each responsive breakpoint. No operational scripts or credentials belong in this repository.
