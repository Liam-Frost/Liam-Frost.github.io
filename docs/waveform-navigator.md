# Waveform navigator

The desktop home page has one SVG rail, 18 visual segments and a separate semantic button for each section that actually exists. `useSections` measures the real document and responds to content, image and size changes; the rail maps positions to document positions, while the active mark tracks scrolling. The existing hash router and `ScrollManager` perform navigation and restore saved scroll positions on back/forward. The rail is hidden below 1280px or without a hover-capable fine pointer; the existing mobile navigation remains available. Other routes currently have only one meaningful top-level section, so do not show the rail.

`useWaveMotion` combines a damped Gaussian pointer peak, scroll progress and a quieter audio contribution in one requestAnimationFrame loop. It updates SVG attributes without React renders and stops when idle or hidden. Reduced-motion disables pointer and audio motion while retaining section buttons and progress. The preview uses existing theme tokens and derives titles and summaries from the rendered section content.

The custom player owns its single HTMLAudioElement and playback events. `audio-visualization.ts` observes that same element using `captureStream` (or Firefox's `mozCaptureStream`) and an AnalyserNode, connected only to the captured stream, never to the destination. This does not insert a MediaElementAudioSourceNode into the original playback path or modify its CORS mode. If the browser cannot capture, rejects the stream, or provides only silence because of CORS, the player continues normally and the rail uses a small synthetic signal during confirmed playback. Extended genuine silence can also trigger this fallback. Captured tracks, nodes and the AudioContext are released on player unmount; the context suspends while paused.

Spotify playback state comes from the official IFrame API in an opaque, sandboxed bridge. Confirmed playback drives synthetic motion, while pause, missing events or a failed bridge return the rail to static. Spotify audio and iframe DOM are never accessed. Synthetic motion is not real frequency data. The main page keeps its strict script CSP; Spotify’s API executes only inside the isolated bridge because the official loader requires dynamic evaluation. The bridge validates message source and a per-mount random token; the public page accepts only messages from its current opaque child. If the bridge fails, a regular Spotify iframe remains available without visualization.

`apps/api/test/waveform.test.ts` covers navigation boundaries, Gaussian shape, synthetic bounds, capture cleanup and unsupported-capture fallback. Browser checks should cover audio output and actual frequency data, keyboard/focus, pointer transitions, section navigation/history, reduced motion and each responsive breakpoint. No operational scripts or credentials belong in this repository.
