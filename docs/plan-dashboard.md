# 执行计划：后台概览（Stage 20）

状态：已确认，已完成（Stage 20）。

## 目标

后台首页「概览」不再只是四个模块的入口（侧边栏已经有了），而是打开后台时一眼看到：网站现在怎么样、账号和外部服务是否正常、有什么需要处理。

## 设计

从上到下：

1. **今日速览**：当前在线人数（最近 5 分钟）、今日浏览量、访客、访问，与昨天同一时段比较；近 7 天浏览量的小趋势图。点击进入「统计」。没有数据库或关闭统计时显示说明。
2. **待处理**：按规则自动生成，每条写明数量并能直接跳到要处理的地方；没有事项时显示“暂无待处理”。首批规则：
   - 引用外链、尚未转为本站托管的照片（跳到照片页，只看引用的照片）；
   - 公开但缺少英文标题的照片和项目；
   - 公开但没有封面的项目；
   - 已看完、读完或玩过但没有评分的收藏（不含音乐）；
   - Steam 已连接但超过 30 天没有同步；
   - 外部服务最近一次请求失败（之后没有成功过）。
3. **账号与服务**：每项一行，状态点 + 一句话 + 操作。
   - Steam：账号名、上次同步时间；按钮打开 Steam 游戏库对话框（连接或同步）。
   - Spotify：已连接的账号，或未配置 / 未连接；按钮打开 Spotify 账号对话框。
   - TMDB、IGDB、Google Books：是否配置了 key；Bangumi、AniList、Open Library 无需 key。都显示最近一次成功和失败的时间。
   - 只显示是否配置，不返回 key 本身。R2 和备份等 Stage 10 / 19c 之后再加。
4. **内容概况**：照片、项目、收藏、人物、歌单的数量，各附一行细分（如「照片 120 · 隐藏 3 · 引用 40」；收藏按类型分，列出在看的数量）。点击进入对应页面。
5. **最近动态**：最近的导入和同步任务及结果；最近编辑的内容（6 条），点击进入编辑。
6. **快捷操作**：添加照片、新建项目、添加收藏，代替原来的四个入口卡片。

## 实现

- **一个汇总接口** `GET /api/admin/dashboard`（只有登录后可用）：后端复用现有的仓库、统计、Steam、Spotify 和外部服务状态，一次返回。每一块单独取数，某一块失败只把这一块标成错误，其余照常返回；页面上只有那一块显示错误。
- **不改数据库结构**，不需要新迁移。统计服务增加一个读取最近任务和外部服务状态的方法（不限日期范围）。
- **前端**复用现有的卡片、徽章、Tooltip 和统计页的数字格式，不引入新的界面库。手机上单列，待处理排在今日速览之后。
- 照片页支持 `?referenced=1`（只看引用外链的照片）；收藏页支持 `?open=steam|spotify` 直接打开对应对话框，供概览跳转。
- 测试：汇总接口的各块内容、待处理规则、某一块失败时其余照常、未登录拒绝、不泄露 key。

## 不做

- 存储占用、R2、备份状态（等 Stage 10 / 19c）。
- 可配置的待处理规则、忽略某条待处理。
- 实时推送；页面每分钟刷新一次在线人数和今日数据。
