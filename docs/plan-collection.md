# 执行计划：收藏模块（电影、剧集、动漫、音乐）

状态：已确认，执行中（2026-10-31）；Stage 11、12 已完成。阶段编号接在 Stage 10（VPS 部署与 CI/CD）之后，但可以先于 Stage 10 开工（见“顺序”）。

## 目标

1. 在网站上展示看过、在看、想看的电影、剧集和动漫，以及喜欢的音乐，附带评分和多语言短评。
2. 后台逐条添加：搜索外部资料库，自动填好资料和海报，再补上个人记录。
3. 音乐可以从 Spotify 收藏夹导入，也可以手动添加；音乐收藏同时作为右下角播放器的播放列表。

## 已确定的决定

- 不考虑中国大陆的可访问性。
- 电影、剧集、动漫没有现成的记录，逐条手动添加；不做豆瓣、Letterboxd 等导入。
- 音乐：从 Spotify 收藏夹导入，加上手动添加。
- 评分为五分制。
- 短评支持多语言（和项目一样的五种语言，没填的语言回退到其它语言）。
- “想看”是否在网站上显示：后台有总开关，每个条目也可以单独设置是否公开。

## 总体设计

### 数据模型

新增一张 `MediaItem` 表，所有类型共用：

| 字段 | 说明 |
| --- | --- |
| `id` | 不变的 UUID |
| `kind` | `movie` / `tv` / `anime` / `track` / `album` |
| `source`、`sourceId` | 资料来源和外部 ID（`tmdb`、`bangumi`、`spotify`、`itunes`，或 `manual`），同一来源同一 ID 不能重复添加 |
| `title`、`originalTitle` | 多语言标题（JSON）和原名 |
| `year`、`genres`、`credits` | 年份、类型标签、导演 / 制作公司 / 艺人等 |
| `overview` | 资料库的简介（多语言，可以修改） |
| `poster` | 本地保存的海报或封面，走现有的图片流程（多尺寸 WebP） |
| `status` | 影视：`want`（想看）/ `watching`（在看）/ `done`（看过）/ `dropped`（弃了）；音乐不用 |
| `rating` | 1-5，空表示未评分 |
| `review` | 多语言短评 |
| `watchedOn`、`rewatchCount` | 看完的日期、重看次数 |
| `progress` | 剧集 / 动漫的集数进度（例如 `8/12`），可选 |
| `extra` | 各类型专属信息（JSON）：音乐的试听地址、时长、ISRC、专辑等 |
| `inPlayer` | 音乐：是否加入右下角播放器 |
| `featured`、`visibility`、`sortOrder` | 首页精选、公开 / 隐藏、排序 |

网站级的设置存在现有的 `Setting` 表（`collection` 键）：

- 各类型是否在网站上显示（电影 / 剧集 / 动漫 / 音乐）。
- “想看”总开关：关闭时，所有“想看”条目都不在网站上显示，无论条目本身是否公开。

### 资料来源（都由服务器调用）

| 类型 | 来源 | 说明 |
| --- | --- | --- |
| 电影、剧集 | TMDB | 免费，需要申请 API key（`TMDB_API_KEY`）；有中、繁、英、法、日标题和简介；页面需要按 TMDB 条款注明数据来源 |
| 动漫 | Bangumi（番组计划） | 官方开放接口，无需 key；中日资料最全。动漫也可以改用 TMDB 搜索 |
| 音乐（手动添加） | iTunes 搜索接口 | 官方公开接口，无需 key；有封面和 30 秒试听 |
| 音乐（导入） | Spotify Web API | 官方接口，你的账号授权一次后读取收藏夹和自己的歌单 |
| 任何类型 | 手动 | 搜不到时手动填写并上传海报 |

海报和封面下载后存到自己的服务器：访客只访问你的网站，不依赖外部图片地址，也不会因为外部网站改地址而失效。

### 音乐试听的来源

Spotify 官方接口不再给新应用提供试听地址，所以导入的歌曲按顺序找试听：

1. 用歌名、艺人和时长在 iTunes 上匹配，取官方试听地址。
2. 匹配不到时，读取 Spotify 单曲嵌入页里的试听地址（和现在的歌单同步一样，不是公开接口）。
3. 都没有时，后台标出“无试听”，可以手动改匹配或者不加入播放器。

## Stage 11：影视收藏的数据与后台（已完成）

- Prisma `MediaItem` 模型和迁移，仓库层（Prisma + 测试用的内存实现）。
- 后台接口：增删改查、排序、海报上传或替换、按来源搜索（`/api/admin/media/search?source=tmdb|bangumi&kind=...&q=...`）、按搜索结果导入（服务器拉取详情和海报）。
- 后台“收藏”页面：
  - 按类型分标签页，按状态筛选，搜索框。
  - “添加”：选类型 → 搜索 → 选中结果 → 进入编辑页，资料已填好。也可以跳过搜索手动填写。
  - 编辑页：五种语言的标题、简介、短评；状态、五星评分、看完日期、重看次数、集数进度；类型标签；公开、精选。
  - 设置面板：各类型显示开关、“想看”总开关。
- 测试：接口、校验、搜索和导入（外部接口用假数据）、可见性规则（总开关 + 条目开关）。

需要你准备：TMDB 账号和 API key（申请时填个人网站用途即可）。

完成标准：后台能通过搜索添加电影、剧集、动漫，海报保存在本地；手动添加也可以。

## Stage 12：前台收藏页（已完成）

- `/collection` 页面：电影、剧集、动漫、音乐标签页；海报墙和列表两种视图；按状态、年份、类型、评分筛选；点开条目是详情抽屉（海报、资料、评分、短评、外部链接）。
- 首页“最近在看”小区块：最近更新的 4 个公开条目（建议放在项目区之后、精选照片之前，开工前给你看效果）。
- 导航新增“收藏”；五种语言的文案；TMDB 来源说明。
- 遵守可见性：隐藏条目、关闭的类型、关闭“想看”时的想看条目都不出现在公开接口里。

完成标准：后台添加的公开条目在收藏页和首页正确显示，开关立即生效。

## Stage 13：音乐收藏与播放器

- 手动添加：iTunes 搜索 → 选中 → 自动带封面和试听。
- Spotify 导入：
  - 后台“连接 Spotify”，你授权一次（只读权限：收藏夹、歌单），服务器保存刷新令牌。
  - 选择导入“已点赞的歌曲”或某个歌单；按 Spotify ID 去重，重复导入只补充新歌。
  - 自动匹配试听（见上文），后台列出没有试听的歌，可以手动修正。
- 播放器改为播放“加入播放器”的音乐收藏，保留随机、顺序、音量、自动收起等设置；卡片上的链接优先打开 Spotify，其次 Apple Music。
- 现在的“按 Spotify 歌单链接同步”改为一次性导入的方式，播放器运行时不再依赖它。

需要你准备：在 Spotify Developer 上创建一个应用，拿到 Client ID 和 Client Secret，填好回调地址（我会给出具体步骤）。开发模式下只有你自己的账号需要授权，够用。

完成标准：收藏夹导入后，播放器播放的是你的收藏；手动添加的歌也会出现在播放器里。

## 顺序

Stage 10（VPS 部署）需要你提供 VPS 和 DNS 信息。在那之前，可以先做 Stage 11-13；部署时一起上线。如果你更想先上线，也可以先做 Stage 10。

## 风险与注意

- TMDB 和 Bangumi 的接口条款：注明来源，控制请求频率；海报只在添加时下载一次。
- Spotify 的开发者政策近年变动较多（例如开发模式的限制）；导入失败不影响已导入的歌曲和播放器。
- Spotify 单曲嵌入页不是公开接口，只作为试听的后备来源。
