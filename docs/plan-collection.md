# 执行计划：收藏模块（电影、剧集、动漫、音乐、图书、漫画、游戏、人物）

状态：已确认，执行中；Stage 11、12、13 已完成，Stage 14-16（关联、人物、新板块）已确认待做。阶段编号接在 Stage 10（VPS 部署与 CI/CD）之后，但可以先于 Stage 10 开工（见“顺序”）。

## 目标

1. 在网站上展示看过、在看、想看的电影、剧集和动漫，以及喜欢的音乐，附带评分和多语言短评。
2. 后台逐条添加：搜索外部资料库，自动填好资料和海报，再补上个人记录。
3. 音乐可以从 Spotify 收藏夹导入，也可以手动添加；音乐收藏同时作为右下角播放器的播放列表。
4. 加入图书、漫画、游戏板块，以及人物（演员、导演、歌手、作家、漫画家、配音等）。
5. 条目之间可以关联：歌曲是某部作品的主题曲或插曲，影视改编自漫画或图书，人物参与了哪些作品；网站上可以沿着关联跳转。

## 已确定的决定

- 不考虑中国大陆的可访问性。
- 电影、剧集、动漫没有现成的记录，逐条手动添加；不做豆瓣、Letterboxd 等导入。
- 音乐：从 Spotify 收藏夹导入，加上手动添加。
- 评分为五分制。
- 短评支持多语言（和项目一样的五种语言，没填的语言回退到其它语言）。
- “想看”是否在网站上显示：后台有总开关，每个条目也可以单独设置是否公开。
- 图书、漫画、游戏继续用 `MediaItem` 表，作为新的 `kind`；人物不打分、没有观看状态，单独一张表。
- 人物的身份（演员、导演、作者等）记在人物和作品的关联上，不记在人物本身：同一个人可以在不同作品里有不同身份。
- 关联用一张通用的关系表，只存一条，两边页面都显示，反向的说法自动生成。

## 总体设计

### 数据模型

新增一张 `MediaItem` 表，所有类型共用：

| 字段 | 说明 |
| --- | --- |
| `id` | 不变的 UUID |
| `kind` | `movie` / `tv` / `anime` / `track` / `album` |
| `source`、`sourceId` | 资料来源和外部 ID（`tmdb`、`bangumi`、`spotify`、`itunes`，或 `manual`），同一来源同一 ID 不能重复添加 |
| `title`、`originalTitle` | 多语言标题（JSON）和原名 |
| `year`、`genres`、`credits` | 年份、类型标签、导演 / 制作公司 / 艺人等 |
| `overview` | 资料库的简介（多语言，可以修改） |
| `poster` | 本地保存的海报或封面，走现有的图片流程（多尺寸 WebP） |
| `status` | 影视：`want`（想看）/ `watching`（在看）/ `done`（看过）/ `dropped`（弃了）；音乐不用 |
| `rating` | 1-5，空表示未评分 |
| `review` | 多语言短评 |
| `watchedOn`、`rewatchCount` | 看完的日期、重看次数 |
| `progress` | 剧集 / 动漫的集数进度（例如 `8/12`），可选 |
| `extra` | 各类型专属信息（JSON）：音乐的试听地址、时长、ISRC、专辑等 |
| `inPlayer` | 音乐：是否加入右下角播放器 |
| `featured`、`visibility`、`sortOrder` | 首页精选、公开 / 隐藏、排序 |

网站级的设置存在现有的 `Setting` 表（`collection` 键）：

- 各类型是否在网站上显示（电影 / 剧集 / 动漫 / 音乐）。
- “想看”总开关：关闭时，所有“想看”条目都不在网站上显示，无论条目本身是否公开。

### 资料来源（都由服务器调用）

| 类型 | 来源 | 说明 |
| --- | --- | --- |
| 电影、剧集 | TMDB | 免费，需要申请 API key（`TMDB_API_KEY`）；有中、繁、英、法、日标题和简介；页面需要按 TMDB 条款注明数据来源 |
| 动漫 | Bangumi（番组计划） | 官方开放接口，无需 key；中日资料最全。动漫也可以改用 TMDB 搜索 |
| 音乐（手动添加） | iTunes 搜索接口 | 官方公开接口，无需 key；有封面和 30 秒试听 |
| 音乐（导入） | Spotify Web API | 官方接口，你的账号授权一次后读取收藏夹和自己的歌单 |
| 任何类型 | 手动 | 搜不到时手动填写并上传海报 |

海报和封面下载后存到自己的服务器：访客只访问你的网站，不依赖外部图片地址，也不会因为外部网站改地址而失效。

### 音乐试听的来源

Spotify 官方接口不再给新应用提供试听地址，所以导入的歌曲按顺序找试听：

1. 用歌名、艺人和时长在 iTunes 上匹配，取官方试听地址。
2. 匹配不到时，读取 Spotify 单曲嵌入页里的试听地址（和现在的歌单同步一样，不是公开接口）。
3. 都没有时，后台标出“无试听”，可以手动改匹配或者不加入播放器。

## Stage 11：影视收藏的数据与后台（已完成）

- Prisma `MediaItem` 模型和迁移，仓库层（Prisma + 测试用的内存实现）。
- 后台接口：增删改查、排序、海报上传或替换、按来源搜索（`/api/admin/media/search?source=tmdb|bangumi&kind=...&q=...`）、按搜索结果导入（服务器拉取详情和海报）。
- 后台“收藏”页面：
  - 按类型分标签页，按状态筛选，搜索框。
  - “添加”：选类型 → 搜索 → 选中结果 → 进入编辑页，资料已填好。也可以跳过搜索手动填写。
  - 编辑页：五种语言的标题、简介、短评；状态、五星评分、看完日期、重看次数、集数进度；类型标签；公开、精选。
  - 设置面板：各类型显示开关、“想看”总开关。
- 测试：接口、校验、搜索和导入（外部接口用假数据）、可见性规则（总开关 + 条目开关）。

需要你准备：TMDB 账号和 API key（申请时填个人网站用途即可）。

完成标准：后台能通过搜索添加电影、剧集、动漫，海报保存在本地；手动添加也可以。

- 遵守可见性：隐藏条目、关闭的类型、关闭“想看”时的想看条目都不出现在公开接口里。

完成标准：后台添加的公开条目在收藏页和首页正确显示，开关立即生效。

## Stage 13：音乐收藏与播放器（13a 已完成：iTunes、歌单导入、播放器；13b 已完成：连接 Spotify 账号导入已点赞歌曲和自己的歌单，Spotify 嵌入播放器）

- 手动添加：iTunes 搜索 → 选中 → 自动带封面和试听。
- Spotify 导入：
  - 后台“连接 Spotify”，你授权一次（只读权限：收藏夹、歌单），服务器保存刷新令牌。
  - 选择导入“已点赞的歌曲”或某个歌单；按 Spotify ID 去重，重复导入只补充新歌。
  - 自动匹配试听（见上文），后台列出没有试听的歌，可以手动修正。
- 播放器改为播放“加入播放器”的音乐收藏，保留随机、顺序、音量、自动收起等设置；卡片上的链接优先打开 Spotify，其次 Apple Music。
- 现在的“按 Spotify 歌单链接同步”改为一次性导入的方式，播放器运行时不再依赖它。

需要你准备：在 Spotify Developer 上创建一个应用，拿到 Client ID 和 Client Secret，填好回调地址（我会给出具体步骤）。开发模式下只有你自己的账号需要授权，够用。

完成标准：收藏夹导入后，播放器播放的是你的收藏；手动添加的歌也会出现在播放器里。

## Stage 14：条目关联与人物

### 数据

`Person` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | 不变的 UUID |
| `name`、`originalName` | 多语言名字（JSON）和原名 |
| `photo` | 头像，走现有的图片流程 |
| `bio` | 多语言简介，可以修改 |
| `links` | 外部链接：TMDB、Spotify、Apple Music、维基等 |
| `source`、`sourceId` | `tmdb` / `spotify` / `anilist` / `manual`，同一来源同一 ID 不能重复 |
| `visibility`、`featured` | 公开 / 隐藏、精选 |

`MediaRelation` 表：

| 字段 | 说明 |
| --- | --- |
| `fromId`、`fromType` | 起点：条目或人物 |
| `toId`、`toType` | 终点：条目 |
| `type` | 关系类型，见下表 |
| `role` | 人物关系的身份：`director` / `actor` / `voice` / `singer` / `composer` / `author` / `illustrator` / `developer` 等 |
| `note` | 多语言备注，例如“第 12 集插曲”“饰 某某” |
| `sortOrder` | 同一组里的顺序 |

| 关系 | 例子 | 对方页面显示 |
| --- | --- | --- |
| `soundtrack`（主题曲 / 片尾曲 / 插曲 / 配乐，用 `role` 区分） | 歌曲 → 动漫、电影、剧集、游戏 | 原声 |
| `adaptation` | 电影、剧集、动漫 → 漫画、图书；游戏 → 漫画 | 被改编为 |
| `sequel` | 作品 → 前作 | 续作 |
| `related` | 任意两个条目（外传、同一系列等） | 相关 |
| `credit` | 人物 → 作品（带 `role`） | 参与者 |

规则：

- 同样的两端加同样的关系和身份只能有一条；删掉条目或人物时，相关的关联一起删除。
- 公开接口只返回两端都公开的关联（遵守现有的类型开关、“想看”开关和条目可见性）。

### 后台

- 人物管理页：搜索 TMDB 人物，或者手动添加；编辑名字、头像、简介、链接。
- 条目编辑器里的“关联”区：搜索收藏里的条目或人物，选关系类型、身份，填备注；可以拖动排序。
- 自动建议，由你勾选确认：
  - 从 TMDB 添加电影 / 剧集时，可以顺带导入导演和主演（默认前几位）。
  - 歌曲已有歌手名：一键为歌手建人物并关联（Spotify 导入的歌曲带艺人 ID，可以去重）。
  - AniList 的改编、续作数据：原作已经在收藏里时提示关联。

### 网站

- 条目详情里按组显示关联（原声、原作、改编、前作 / 续作、参与者），点击跳转到对应条目。
- 人物页：头像、简介、链接，以及“收藏里和 TA 有关的作品”，按身份分组。
- 收藏页新增“人物”标签（有公开人物时才显示）。

完成标准：可以把主题曲关联到动漫、把导演关联到电影，两边详情页都能看到并互相跳转；人物页列出 TA 在收藏里的作品。

## Stage 15：图书与漫画

- 新的 `kind`：`book`、`comic`。状态的说法按类型变：想读 / 在读 / 读过 / 弃了（影视仍是想看 / 在看 / 看过）。
- `extra` 里的专属信息：图书有作者、出版社、ISBN、页数；漫画有作者、卷数、连载状态。
- 资料来源：

| 类型 | 来源 | 说明 |
| --- | --- | --- |
| 图书 | Open Library（主）、Google Books（补充） | 都不需要 key；Open Library 有封面接口，Google Books 中文书资料更全 |
| 漫画 | AniList（主）、Bangumi（补充） | 和动漫同源，有罗马音；改编关系可以直接给 Stage 14 的建议用 |

- 作者在添加时可以建成人物并关联（`credit`，身份 `author` / `illustrator`）。
- 进度：漫画按卷或话，图书按页，可选。
- 后台和网站：新的标签和筛选；类型开关和“想看”开关覆盖新类型。

完成标准：可以搜索添加图书和漫画，动漫可以关联到原作漫画，网站上能看到并跳转。

## Stage 16：游戏

- 新的 `kind`：`game`。状态：想玩 / 在玩 / 玩过 / 弃了。
- `extra`：平台、开发商、发行商，可选的游玩时长。
- 资料来源：IGDB（需要你申请一个 Twitch 开发者应用，拿到 Client ID 和 Secret，免费）；RAWG 作为后备（需要 API key）。
- 开发商可以建成人物或团体并关联（`credit`，身份 `developer`）；游戏原声可以用 `soundtrack` 关联歌曲。

需要你准备：Twitch 开发者应用的 Client ID 和 Client Secret（填进 `apps/api/.env`，具体步骤到时给出）。

完成标准：可以搜索添加游戏，关联游戏原声和改编作品。

## Stage 17（可选）：年度回顾

- 按年份统计看过的数量（按类型）、评分分布、类型占比，按月份的时间线。
- 收藏页顶部的年度摘要，例如“2026 年看了 43 部电影”。

## 顺序

Stage 10（VPS 部署）需要你提供 VPS 和 DNS 信息。在那之前，可以先做 Stage 11-16；部署时一起上线。如果你更想先上线，也可以先做 Stage 10。

Stage 14 先做：现有的电影、剧集、动漫、音乐马上就能用上关联和人物；Stage 15 的作者和改编关系也建立在它上面。Stage 16 需要你先申请 IGDB 凭证，可以和 Stage 15 换顺序。

## 风险与注意

- TMDB 和 Bangumi 的接口条款：注明来源，控制请求频率；海报只在添加时下载一次。
- Spotify 的开发者政策近年变动较多（例如开发模式的限制）；导入失败不影响已导入的歌曲和播放器。
- Spotify 单曲嵌入页不是公开接口，只作为试听的后备来源。
- 人物照片和简介来自 TMDB 等资料库，同样要注明来源；只展示和你收藏有关的公众人物信息。
- 自动建议只给候选，不自动建立关联，避免同名人物和错误的改编关系混进来。
- IGDB 的凭证有有效期，服务器需要自动续期；IGDB 不可用时仍可以手动添加游戏。
