# 执行计划：访问分析（Stage 18）

状态：已确认，执行中；18a 已完成。参照 `internal-developer-tools-portal` 的使用分析，但按个人主页的访客、内容和隐私要求重新设计。

## 目标

1. 知道谁在看（国家、语言、设备）、从哪来（来源网站、搜索引擎、推广链接）、对什么感兴趣（每个项目、照片、收藏条目、歌曲）。
2. 在后台 Analytics 页面查看，并在现有的项目 / 照片 / 收藏列表和编辑页显示每条内容的近期浏览量。
3. 监控网站自身的体验和运行：页面性能、接口错误、导入与同步任务、外部数据源凭证。
4. 不打扰访客：不用 Cookie、不在浏览器里保存访客标识、不保存 IP，不需要同意横幅。

已确认的决定：

- 采用无 Cookie 方案；接受不能统计“回访访客”。
- 做国家统计。
- 统计数据只在后台查看，网站公开部分暂不展示（例如“热门项目”）。

## 与 internal-developer-tools-portal 的区别

|          | portal                       | 个人主页                               |
| -------- | ---------------------------- | -------------------------------------- |
| 访客     | 内部、少量、可信             | 公开、匿名、多国家，有大量爬虫         |
| 核心问题 | 工具用得多不多、服务是否在线 | 谁在看、从哪来、对哪些内容感兴趣       |
| 统计对象 | 工具点击、搜索               | 页面、作品、照片、收藏条目、歌曲、外链 |
| 访客识别 | localStorage 中的匿名访客 ID | 服务端每日轮换盐的哈希，不跨天         |
| 健康监控 | 探测几十个外部工具           | 网站自身与导入用的外部数据源           |
| 存储     | 独立 SQLite                  | 现有 PostgreSQL（Prisma 迁移）         |

沿用 portal 的部分：指标口径集中定义并用于界面提示和导出；原始事件保留期 + 永久日汇总；查询时整天读汇总、当天实时算；事件批量上报、服务端校验并补全字段、按 IP 限流、短时间重复点击合并；小人数阈值；时间筛选写在 URL 中并与上期对比；CSV / JSON 导出（带 BOM、防公式注入）；清除数据需输入确认；演示数据写独立数据库。

## 隐私设计

- **访客去重**：服务端计算 `hash(每日随机盐 + IP + User-Agent)` 作为当天的访客标识；盐只保存在内存和数据库中当天一份，次日轮换并销毁旧盐。能统计日独立访客，不能跨天关联同一个人；多日范围的“访客”是每日访客之和（界面注明为近似）。
- **会话**：会话 ID 由前端生成并保存在 `sessionStorage`（关闭标签页即消失），30 分钟无活动开始新会话。
- **不保存 IP**：IP 只在请求处理中用于计算哈希、判断国家、限流和排除列表，不写入数据库或日志。
- **国家**：只记录国家代码。优先读取 Cloudflare 的 `CF-IPCountry`（如果 Stage 10 使用 Cloudflare 代理），否则使用本地 GeoLite2 Country 数据库（`ANALYTICS_GEOIP_DB`，可选，没有时国家为“未知”）。
- **尊重浏览器设置**：GPC（`navigator.globalPrivacyControl`）或 DNT 打开时不上报。
- **隐私说明页**：网站增加一页简短说明（五种语言）：收集什么、不收集什么、保留多久、如何关闭。
- **小人数阈值**：热力图、按国家 / 设备的细分中，独立访客少于 `ANALYTICS_MIN_GROUP_SIZE`（默认 3）时不显示数值。

## 采集

### 公共维度（服务端补全，不信任前端提交的时间和名称）

时间、当日访客哈希、会话 ID、页面路由模板（如 `/projects/:slug`）、界面语言、设备类型（手机 / 平板 / 桌面，由 UA 判断）、浏览器大类、国家代码。

### 事件

| 事件                | 含义                                                                           | 附带                                                                              |
| ------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| `page_view`         | 首次加载与站内路由切换（HashRouter，监听路由变化）                             | 路由模板；会话首页另记来源域名（只保留域名）与 UTM 参数                           |
| `content_view`      | 打开具体内容：项目详情、照片大图、收藏条目面板、人物面板、歌单 / 专辑 / 艺人页 | 内容类型与 ID（服务端校验存在且公开）                                             |
| `music_play`        | 开始播放歌曲                                                                   | 歌曲 ID、播放器类型（自带 / Spotify）、入口（角落播放器 / 收藏页按钮 / 播放全部） |
| `outbound_click`    | 点击外链                                                                       | 目标域名、位置（项目演示、GitHub、Spotify、Apple Music、社交账号等）              |
| `collection_filter` | 收藏页切换标签与视图                                                           | 类别、视图（封面 / 列表 / 专辑 / 艺人 / 歌单 / 回顾）                             |
| `engagement`        | 离开或隐藏页面时上报一次页面的实际可见秒数                                     | 路由模板、秒数（上限 30 分钟）                                                    |
| `web_vital`         | 页面体验指标，按 50% 抽样                                                      | LCP / INP / CLS 与路由模板                                                        |

### 不计入

- 爬虫：只有前端 JS 发送事件；另外过滤 bot / crawler / headless UA 与 `navigator.webdriver`。
- 管理员自己：登录后台时在站点同源设置“不统计”标记；`ANALYTICS_EXCLUDE_IPS`（支持 CIDR）排除 CI 等来源。
- GitHub Pages 构建（`VITE_DISABLE_API_FETCH`）不加载统计代码。
- 后台页面、接口轮询、统计查询本身。

### 接收

`POST /api/analytics/events`：公开接口，批量最多 50 条 / 32 KB，离开页面时用 `sendBeacon`；按 IP 限流；只接受已知路由模板和存在的公开内容 ID；事件 ID 主键，重复提交幂等忽略；同一会话同一目标 1 秒内的重复点击合并。

## 存储

| 表                   | 内容                                                                                                                     | 保留                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| `AnalyticsEvent`     | 原始事件                                                                                                                 | `ANALYTICS_EVENT_RETENTION_DAYS`（默认 90） |
| `AnalyticsSession`   | 会话（开始、最后活动、页面数、停留秒数、入口页、来源）                                                                   | 同上                                        |
| `AnalyticsDaily`     | 日汇总（`day, metric, key, value`）：浏览量、访客、会话、内容浏览、播放、外链、来源、国家、语言、设备、Web Vitals 分布等 | 长期                                        |
| `AnalyticsSalt`      | 当日盐                                                                                                                   | 只保留当天                                  |
| `AnalyticsRollupDay` | 已汇总的日期                                                                                                             | 长期                                        |

- 每小时维护一次：汇总已结束的日期（最近两天每次重算），再清理过期原始数据；汇总先删后写，可重复执行。
- 统计时区 `ANALYTICS_TIMEZONE`（默认 `Asia/Shanghai`）。
- 内容被删除后，历史统计以删除前的名称显示并标注“已删除”（保存名称快照）。

## 运行状况数据

- API 记录公开接口的状态码与响应时间（按路由模板），按天汇总 5xx 比例与 P95。
- 导入与同步任务（Spotify、歌单链接、Steam、IGDB / TMDB 等导入）的成功、失败与失败原因写入任务记录。
- 外部数据源凭证状态：最近一次成功 / 失败的时间与原因（例如 Spotify token 失效、key 被拒绝）。

## 后台 Analytics

`<ADMIN_PATH>/analytics`，四个视图，共用时间筛选（今天 / 7 天 / 30 天 / 90 天 / 自定义，写在 URL 中）与“较上期”对比：

1. **总览**：浏览量、访客（近似）、会话、平均停留、跳出率（只看一页且停留不到 10 秒）；访问趋势；热门页面；当前在线（近 5 分钟会话）。
2. **内容**：项目、照片、收藏（按类别）、歌曲、人物、歌单的排行；单个内容详情（趋势、来源、外链点击）；音乐播放次数、两种播放器的用量、整张播放的歌单。现有列表和编辑页显示“近 30 天浏览 / 播放”，并可跳到详情。
3. **来源与受众**：来源域名（搜索引擎、GitHub、社交平台、直接访问）、UTM 活动、国家分布、界面语言、设备与浏览器、活跃时段热力图（小人数阈值）。
4. **体验与运行**：各页面 Web Vitals 的 P75（按 good / needs improvement / poor 着色）、公开接口 5xx 比例与响应时间、导入与同步失败记录、外部数据源凭证状态。

另有：导出 CSV / JSON；清除统计数据（使用统计 / 运行状况 / 全部，输入确认）；`npm run db:seed:analytics-demo` 生成 60 天演示数据到独立数据库（拒绝写入正式库），界面显示“演示数据”。

## 配置

`ANALYTICS_ENABLED`、`ANALYTICS_TIMEZONE`、`ANALYTICS_EVENT_RETENTION_DAYS`、`ANALYTICS_MIN_GROUP_SIZE`、`ANALYTICS_RATE_LIMIT_PER_MINUTE`、`ANALYTICS_EXCLUDE_IPS`、`ANALYTICS_GEOIP_DB`（可选）。
