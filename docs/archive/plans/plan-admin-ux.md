# 执行计划：后台概览与 API 配置页的 UI/UX 优化（Stage 22）

状态：已确认，已完成（Stage 22）。

## 目标

在保留现有设计语言（深蓝侧栏、浅灰背景、白色卡片、克制的圆角和阴影）和全部功能的前提下，改善两个页面的信息架构、层级、空间利用和响应式表现。不新增界面库，不改其他页面的样式。

## API 配置页

- **布局**：多列卡片网格改为单列分组列表（最大宽度约 840px），每组一个白色容器，服务之间用分隔线。
  - 资料来源：TMDB、Google Books、Twitch / IGDB
  - 账号与同步：Spotify、Steam（这两个还需要在收藏页连接账号）
- **收起时**：一行显示服务名、一句话用途、凭据状态和展开箭头。
- **展开时**：一次只展开一个服务，在这一行下方显示字段、配置来源、最近请求结果、帮助说明，以及「保存配置」「取消修改」；「停用」「恢复服务器配置」放在下方的低强调区域。
- **未保存的修改**：每个服务单独保留草稿，切换服务不会丢失；收起的服务显示「有未保存的修改」；有草稿时离开页面先提示。
- **三种状态分开**：
  - 凭据：未配置 / 已配置 / 已停用（后台保存了空配置）。
  - 来源：服务器配置 / 后台配置。
  - 连接：这个页面不检测连接；有记录时显示最近一次请求的结果和时间（TMDB、Google Books、IGDB 来自任务日志；Spotify、Steam 显示账号是否已连接），没有记录就写「未检测」，不显示绿色健康状态。
- **顶部说明**压缩成一行安全提示，细节放到相关字段和操作旁边。
- 保存、停用、恢复的接口和规则不变：留空保留原值、不回显密钥、恢复前确认、处理中不能重复提交、成功后以服务器返回的状态为准。

## 概览页

用一个 12 列网格代替两个各自变长的列：

| 行  | 桌面                                 | 窄屏                    |
| --- | ------------------------------------ | ----------------------- |
| 1   | 4 个等宽 KPI                         | 2 列（320px 也是 2 列） |
| 2   | 待处理（7 列）+ 内容概况（5 列）     | 单列                    |
| 3   | 账号与服务（5 列）+ 最近动态（7 列） | 单列                    |

- **KPI**：数值是视觉重点，用等宽数字；口径用 ⓘ 提示说明；和昨天同一时段比较；近 7 天小图只在有数据时显示，标出日期范围，每根柱子有提示。
- **待处理**：每条任务写清对象和数量，点击进入已筛选好的页面：
  - 照片页支持「只看引用」「缺英文标题」；
  - 项目页支持「缺英文标题」「没有封面」；
  - 收藏页支持「未评分」（任务带上未评分最多的类型）。
- **内容概况**：去掉嵌套的小卡片，改成带分隔线的统计行；收藏各类型的数量放进可展开的明细。
- **账号与服务**：分为「已授权账号」（Steam、Spotify，保留同步和管理入口）和「资料服务」；正常的服务压缩显示，失败和需要处理的排在前面并突出。绿色只表示「最近一次请求成功」，不表示当前一定在线。
- **最近动态**：编辑和导入同步合并成一个时间序列，每条统一为「图标 · 事件 · 对象或结果 · 时间」，长标题截断并保留完整文字。
- **加载**：骨架占位代替「加载中」。

## 接口

只加一个字段：「未评分」任务带上 `kind`（未评分最多的类型），让链接能打开正确的收藏标签。其他接口和统计口径不变，不增加请求。
